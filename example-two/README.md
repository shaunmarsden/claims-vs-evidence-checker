# Worked Example Two: Conflicting Evidence

The first [example](../example/) illustrates a status with an outstanding check and one with old notes. This example uses two fictional notes on the same fence that disagree about whether the work is finished.

- [tracker.md](tracker.md): one item, two notes that disagree
- [output.md](output.md): the status check, which names the conflict rather than averaging the notes or trusting the newer one
- [review.md](review.md): whether it named the conflict and said how to settle it

The output keeps the disagreement visible, but calls both notes specific. The review points out that the first is only a general statement of satisfaction, while the second names a missed section. Neither note establishes whether that section was later finished.

The repository doesn't record which model wrote this status check, or whether it knew what the test was checking. Read it as an illustration of what a good run looks like, not as a logged run.
